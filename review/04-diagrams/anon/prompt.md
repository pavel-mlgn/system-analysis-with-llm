ДИАГРАММА 1: Component diagram (C4)
Покажи все сервисы, базы данных, внешние системы, брокеры сообщений (если есть) и связи между ними.
Используй синтаксис flowchart TB с subgraph для группировки
по контейнерам. Для каждой связи укажи протокол и канал (эндпоинт, топик, очередь).

ДИАГРАММА 2: Sequence diagram — основной успешный сценарий (happy path)
Определи из кода основной сценарий, который завершается успешно.
Покажи полный путь от точки входа до финального результата.
Используй реальные имена классов, методов и каналов из кода.

ДИАГРАММА 3: Sequence diagram — основной сценарий отказа
Определи из кода наиболее показательный сценарий, в котором
запрос не может быть выполнен. Покажи, как система обрабатывает
этот случай, в том числе что происходит с действиями, уже
выполненными к этому моменту.

ДИАГРАММА 4: ER-диаграмма
Все сущности, включая объекты, которые не хранятся в БД, но
передаются между компонентами (например, сообщения), — их поля
с типами и связи с кардинальностью. Если сущности хранятся
в разных базах данных — рисуй отдельную ER-диаграмму для каждой
базы (4а, 4б, …), а объекты, которые не хранятся в БД, — отдельной
диаграммой. Связи по внешним ключам рисуй сплошной линией,
логические связи (через идентификатор, без FK) — пунктирной.
Логические связи между сущностями разных диаграмм перечисли
списком после диаграмм.

ДИАГРАММА 5: Диаграмма состояний
Выбери ключевую бизнес-сущность, у которой есть жизненный цикл
(статусы). Покажи все её состояния и переходы между ними
с условиями перехода. Используй синтаксис stateDiagram-v2.
Если таких сущностей несколько — нарисуй диаграмму для главной,
а остальные перечисли.
